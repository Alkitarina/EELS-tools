# H5 数据格式与总计数

网页导入一个 EELS 谱像时，使用以下根数据集。新增的总计数字段用于参考底图和候选中心，峰分析仍使用原谱像。

| 路径 | 逻辑形状 | 内容 |
| --- | --- | --- |
| `/intensity` | `[ny, nx, nE]` | 源 EELS.data 的原始数值 |
| `/x_nm` | `[nx]` | x 像素中心坐标 |
| `/y_nm` | `[ny]` | y 像素中心坐标 |
| `/energy_meV` | `[nE]` | 源 EELS.ene，保留负能量 |
| `/reference_maps/total_counts` | `[ny, nx]` | 源 EELS.info.totint 的原始数值 |

只要源对象有有效 `info.totint`，新转换必须保存它。不得用当前处理后谱像的求和或任意能窗积分替代，也不能标为 HAADF。总计数必须是实数二维数组，至少含一个有限值，尺寸对应当前对象的 y、x；尺寸不一致时转换报错，不能静默丢弃或裁剪。

EELS 所在组的属性：

- `reference_maps_schema = eels_reference_maps_v1`。
- `total_counts_status = available`：必须包含有效总计数数据集。
- `total_counts_status = missing_in_source`：源对象没有总计数；不创建替代数组。
- `total_counts_status = missing_in_input`：Python 当前加载的数据不含总计数，无法判断原 MAT 是否保存；可检查源 MAT 后重新转换。不能把旧 H5 的遗漏误报为源 MAT 缺失。

总计数数据集的属性：

- `source_field = EELS.info.totint`。
- `axis_order` 描述 **h5py 实际读到的存储维度**：Python 写入为 `y_nm,x_nm`；MATLAB h5write 写入后维度反转，为 `x_nm,y_nm`。即使是方形图，也必须按该声明处理转置。

旧 H5 没有这些声明仍可导入谱像。有总计数但缺少旧版轴声明时，沿用原先按谱像存储方向判断的兼容规则；新格式缺少或使用未知方向则停用该参考图并说明原因。源文件缺失总计数和 H5 遗漏总计数会显示不同提示，其他谱像分析仍可使用。

## 多个 EELS 对象

批量转换仍保持一个 MAT 对应一个同名 H5，并保留相对子目录。只有一个 EELS 对象时，数据在根目录；有多个时，每个变量放在 `/eels/<变量名>/`，其四个谱像/坐标数据集及 `reference_maps/total_counts` 均在该组内，各有自己的总计数和来源。

当前网页一次导入一个根目录谱像，不会猜选多变量档案中的某一组。多变量 MAT 可在 MATLAB 中加载后，逐个调用 `export_eels_to_hdf5(对象, 输出路径)`，分别保存为 `<原文件名>__<变量名>.h5`，再导入网页。批量档案和按对象拆分的文件应分别保存，避免覆盖。

## 转换记录

`matlab/export_eels_to_hdf5.m` 和 `matlab/batch_export_eels_tree_to_hdf5.m` 共用 `matlab/write_eels_reference_maps.m`。批量清单记录 `total_counts_variables` 与 `missing_total_counts_variables`，能查明哪些变量保留了总计数。

批量转换应写入新的输出目录，并保留原 MAT。验证时比较谱像、x/y/能量坐标和总计数与源对象的数值，检查 UI 读取及总计数方向。仓库不包含实验转换结果或历史验证报告。
